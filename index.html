Commodity Disruption Signal & Explanation System

Detects unusual moves in arabica coffee futures, retrieves the news from the days before each move, and either explains the move with cited evidence or declines to. The project measures how often a retrieval pipeline invents a cause, and what it takes to stop it.

Detection
Flags moves with a rolling z-score on daily returns, plus a 10-day cumulative check for moves that build slowly. It caught every known event it was tested on (coffee 4 of 4, crude oil 5 of 5, wheat 4 of 4) with no flags in each commodity’s quiet control period.
Evidence
Retrieves news from GDELT, Google News and industry feeds, limited to the 10 days up to the move, and filters it with a keyword score and a multilingual embedding score. Auditing the stored runs showed that 16% of accepted documents were dated after the move and 20% were syndicated copies. Both are now removed.
Explanation
The model reads each document without being told which way prices moved, and a reason counts only if its quote is found in the document. A fixed rule, not the model, then decides whether to explain. It explained 12 of 16 labelled moves, and all 24 citations pointed to a document the model was shown.
Stress test
Given invented moves on quiet days, it still explained 5 of 12, so the refusal claim failed its first test. A stricter rule built from those failures refuses all 12 on the stored readings and has not yet been run live. Forecasting price direction did no better than chance, and the write-up says so.
Delivery
Ships with a Streamlit dashboard, 305 unit tests that need no network or API key, cached retrieval so the offline evaluations can be rebuilt, and a written evaluation with 95% confidence intervals on every rate.

CrowdWatch

Real-time overcrowding detection for malls, stations and other public places, from ordinary CCTV video. It counts the people in each zone, compares the count with what the zone can safely hold, and warns before it fills up.

Counting
Detects people with YOLOX on ONNX Runtime and follows them with a tracker written for the project in the style of ByteTrack, so the count stays steady when people pass behind each other. It runs on a laptop CPU with no GPU.
Dense crowds
Hands over to a density-map network (DM-Count) when a zone is too packed to pick people out one by one. On the ShanghaiTech Part B benchmark this cut the counting error from 100 people per image to 13, with neither model trained on that data.
Alerts
Forecasts when a zone will be full and raises one alert per episode. Across 60 simulated runs it caught 47 of 51 overcrowding events with 47 alarms, where a per-frame threshold raised 2,920, and it gave advance warning of 44 of the 51 a median of 56 seconds ahead.
Delivery
Ships with a FastAPI dashboard over WebSocket, SQLite storage, Prometheus metrics, an MCP server for AI assistants, Docker and CI, backed by 89 automated tests. It saves only counts, never video or images of people.
